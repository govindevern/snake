# Build and validate Snake's Windows distribution

## Developer prerequisites

- Windows 10/11 x64 with a **64-bit** Python 3.10 or newer for the build machine.
- Internet access only if the developer needs to install the build dependency or Inno Setup. End-user setup is offline.
- Inno Setup 6 to produce `Snake-Setup-1.1.0.exe`. It is not a runtime dependency and is not bundled into Snake.

PyInstaller 6.22.3 is the pinned third-party Python build dependency. Snake itself has no third-party runtime dependencies. Installer and distribution files contain the bundled executable/runtime, README, license, release notes, and build metadata.

Install the build-time dependencies with:

```powershell
python -m pip install -e ".[build]"
winget install --exact --id JRSoftware.InnoSetup --source winget --scope user --accept-package-agreements --accept-source-agreements
```

## Prepare, test, build

Run these commands in PowerShell from the repository root:

```powershell
python -m pip install -e ".[build]"
python -m unittest discover -s tests -v
python build.py --format both --exe-only
```

`--format both` independently builds one-file and one-directory executables and smoke-tests both with Python-specific variables cleared and PATH restricted to the Windows system directory. It selects the single-file executable only if all smoke checks pass; otherwise it selects the verified one-directory folder. Each run gets a unique temporary build-work folder under `build`; prior build-work folders are left alone to avoid deleting locked or unrelated files. The versioned release directory is updated in place only after it is marked as generated by this build.

Expected standalone output is under `release\v1.1.0`, including `standalone\snake.exe` (or the selected standalone directory), `Snake-Standalone-1.1.0.zip`, `BUILD_INFO.txt`, README, license, release notes, and `SHA256SUMS.txt`. The generated files are ignored by Git.

## Build the offline setup program

Install Inno Setup 6 on the developer's Windows build machine. Then run:

```powershell
python build.py --format both
```

If Inno Setup is installed in a nonstandard location, specify its compiler:

```powershell
$env:INNO_SETUP_COMPILER = "D:\Tools\Inno Setup 6\ISCC.exe"
python build.py --format both
```

The build creates `release\v1.1.0\Snake-Setup-1.1.0.exe` and regenerates checksums. If only the standalone program is wanted, use `--exe-only`; this does not claim to build an installer.

The installer script uses one stable Inno Setup AppId for subsequent Snake standalone upgrades. It supports x64 Windows, offers Inno's admin/per-user privilege choice, adds the exact install directory to system or user PATH as appropriate without overwriting other entries, offers an optional Start Menu shortcut, and removes only that PATH entry at uninstall. Changing to a new install directory on upgrade is expected to remove the old Snake PATH entry and add the new one.

## Test generated artifacts

`build.py` tests each executable format from a temporary, unrelated working directory, with no Python path entry, and checks version/help, relative program execution, absolute-path syntax check, runtime library calls, program-directory file access, runtime and syntax failures, exit codes, and REPL input.

For a separately built artifact, set `SNAKE_TEST_EXE` to the absolute executable path and run:

```powershell
$env:SNAKE_TEST_EXE = (Resolve-Path .\release\v1.1.0\standalone\snake.exe).Path
python -m unittest discover -s tests -v
Remove-Item Env:SNAKE_TEST_EXE
```

The installer must additionally be installed, upgraded, and uninstalled on a clean Windows 10/11 x64 virtual machine. Verify user and system PATH separately, pre-existing PATH values and duplicates, a terminal opened after setup, `snake --version` and `snake run` from an unrelated directory, and that uninstall preserves unrelated PATH entries. Do not run destructive installer/uninstaller checks on a machine containing unrelated software. These VM checks cannot be replaced by checking the `.iss` source or a successful compiler exit.

After building the installer, run the automated disposable-machine check from an elevated or standard PowerShell window on a **disposable VM only**:

```powershell
.\tests\test_installer.ps1 -Installer .\release\v1.1.0\Snake-Setup-1.1.0.exe
```

It snapshots and restores the selected registry PATH value, seeds an unrelated sentinel entry, installs (and reinstalls to verify no duplicate entry), checks command resolution in a child process, then uninstalls. To exercise system PATH, use an elevated disposable VM and `-SystemInstall`. If an earlier compatible setup exists, pass it with `-PreviousInstaller <old-setup.exe>` to exercise that upgrade path. This script has not been run unless an installer was actually built and tested on that VM.

## Reproducibility and release checks

Use the same Windows architecture and pinned developer-tool versions for release candidates, record the Python and PyInstaller versions, and preserve `SHA256SUMS.txt` with the release files. The PyInstaller bootstrap/runtime and timestamped Windows PE output can vary with toolchain versions, so the build is repeatable but is not bit-for-bit reproducible across arbitrary environments.

The project does not include a code-signing certificate. Executables and installers built from this source are unsigned and may trigger a Windows SmartScreen or endpoint-protection reputation warning. Signing is a release-management step; do not disable security features to work around a warning.
